# С чего начать — исправленная версия 2

Проект: «Планеты Солнечной системы». Одна таблица, 8 строк, одна страница.
Данные реальные, из таблицы NASA. Это небольшой учебный проект, не коммерческий опыт.

Закрой предыдущий проект. Распакуй этот архив в НОВУЮ папку, чтобы не смешать его с файлами, сохранёнными Power BI из первой версии.

## Быстрый запуск
1. Распакуй весь архив в отдельную папку.
2. Открой SolarSystem.pbip в Power BI Desktop на Windows. Не перемещай файл отдельно от двух соседних папок.
3. Если формат не открывается, включи File → Options and settings → Options → Preview features → Power BI Project (.pbip) save option (Файл → Параметры → Предварительные возможности), затем перезапусти программу. Формулировки могут отличаться по версии.
4. Нажми Home → Refresh (Главная → Обновить). Данные встроены, скачивать их заново не нужно.
5. Для цветов: View → Themes → Browse for themes (Вид → Темы → Выбрать тему), файл Space-theme.json. Это необязательно.
6. Сверь значения ниже, проверь фильтры и сохрани через Save as (Сохранить как) в .pbix.

Здесь проверены данные и JSON-структура. Power BI Desktop в среде подготовки недоступен, поэтому открытие, вычисление DAX/M и внешний вид нужно проверить у тебя.

## Если хочешь собрать сам — это полезнее для обучения
1. Get data → Text/CSV (Получить данные → Текст/CSV): data/Planets.csv.
2. Transform data (Преобразовать данные). Таблицу назови Planets.
3. В Power Query задай Planet и PlanetType как Text (Текст), OrderFromSun и DiameterKm как Whole number (Целое число), остальные — Decimal number (Десятичное число). Если десятичная точка не распознана, используй Change type → Using locale (Изменить тип → С использованием языкового стандарта), English (United States).
4. Close & Apply (Закрыть и применить).
5. Modeling → New measure (Моделирование → Новая мера): добавляй по одной формуле из DAX_measures.txt. Весь файл сразу вставлять не нужно.
6. Выдели столбец Planet → Sort by column (Сортировать по столбцу) → OrderFromSun.
7. Добавь визуализации из таблицы ниже.

| Элемент | Поля |
|---|---|
| Slicer (Срез) | PlanetType |
| Slicer (Срез) | Planet |
| Card (Карточка) | Planet Count |
| Card (Карточка), подпись Largest diameter | Diameter (km) |
| Card (Карточка), подпись Longest year | Year Length (Earth years) |
| Clustered bar chart (Линейчатая диаграмма) | Ось Y: Planet, ось X: Diameter (km) |
| Clustered bar chart (Линейчатая диаграмма) | Ось Y: Planet, ось X: Year Length (Earth years) |
| Table (Таблица) | Planet, PlanetType, Distance (million km), Gravity (m per s2), Diameter vs Earth |

В таблице отключи Total (Итог). Суммировать диаметры и расстояния разных планет здесь бессмысленно. Диаграммы отсортируй по Planet по возрастанию — порядок задаёт OrderFromSun.

## Проверка
Без фильтров: 8 планет; максимальный диаметр 142 984 км; самый длинный год около 163,72 земного года.
Фильтр Terrestrial (земного типа): 4 планеты; максимальный диаметр 12 756 км; максимальная длина года около 1,88 года.
Фильтр Gas giant (газовый гигант): 2 планеты. Ice giant (ледяной гигант): 2 планеты.
При выборе Earth: Diameter vs Earth = 1,00. При выборе Jupiter: примерно 11,21.
В отчёте порядок планет должен идти от Mercury до Neptune. Проверяй фильтры по отдельности, предварительно очищая предыдущий выбор.

## Что важно понять
Одна строка = одна планета. PlanetType задаёт группу. Measure (мера) пересчитывается в текущем Filter context (контексте фильтрации).
MAX берёт максимальное значение: в строке Jupiter это значение Юпитера, а в карточке без фильтров — максимальное среди всех планет.
DIVIDE делит с обработкой нулевого знаменателя. В мере Diameter vs Earth функция REMOVEFILTERS снимает выбор планет только при поиске диаметра Земли, чтобы база сравнения оставалась постоянной.
Год переведён в земные годы делением на 365,25. Это приближённый перевод, не утверждение о точной длительности земного тропического года.
